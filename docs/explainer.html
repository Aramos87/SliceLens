Slice Lens

Headline accuracy is a screenshot, not a finding.

A single number looks like a win. Slice Lens names the slice that was carrying the errors, rewrites what you’d have reported, and asks a held-out split whether the name still holds.

The problem

Eval dashboards ship an average. The average is true as arithmetic and false as a story. Errors are not sprinkled evenly. On Negation trap they pile up on prompts that contain a negation. The model is at 14% there, and 96% everywhere else. The 87.8% is a blend that hides a systematic failure behind a number you would paste into a launch post.

Clustering the leftovers does not fix this. Cluster 3 is not a sentence. A reviewer cannot grep it, unit-test it, or disagree with it.

How we solve it

One click. Four named predicates. No uploads. No API keys.

  1. Vanity number — overall accuracy, shown on purpose.
  2. Interpretable slice — a boolean with an English label: has negation.
  3. Rewrite — accuracy on the complement: you’d have reported.
  4. Confirm — the same predicate on a held-out split. If it does not replicate, the miss stays on screen.

Architecture

The product is one page talking to one engine. Reviewers are not a data pipeline.

The bet

A tiny, named, confirmable predicate is worth more than a beautiful unlabeled map. Don’t ship the screenshot. Name the slice.
